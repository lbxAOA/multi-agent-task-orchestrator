# 持续优化机制

本 Skill 是可验证的团队运行手册，不是不断堆叠的提示词。优化必须来自真实任务证据，并以版本化变更交付。

## 核心循环

每个实际发生委派或多成员协作的任务结束后：

1. **收集证据**：保存任务契约、执行通道、任务单、修改范围、验收命令、退出状态和 A2A `context_id`（如有）。
2. **填写复盘**：从 `retrospective-template.md` 创建记录，明确成功、失败、返工、冲突、超时和未验证项。
3. **提出候选规则**：每条候选规则必须包含“触发条件 → Hermes 动作 → 验收标准”。
4. **筛选**：仅在同类问题至少两次出现、单次造成明显风险，或用户明确要求改变行为时，才写入主 Skill。
5. **最小改动**：优先精确更新 `SKILL.md`，避免重写无关章节或重复近义规则。
6. **验证新规则**：在下一次匹配任务中检查它是否实际改变委派、调度或验收行为。
7. **发布版本**：更新 frontmatter 版本、`CHANGELOG.md` 并发布；只有验证后才能称规则有效。

Hermes 独自完成的简单任务不必复盘，除非出现高风险失败或用户要求记录。

## 候选规则质量门槛

规则必须同时满足：

- **可触发**：明确何时适用。
- **可执行**：说明 Hermes 要做什么，不使用“注意”“尽量”等模糊词。
- **可验证**：能由 diff、测试、委派记录、A2A 回复或退出码验证。
- **通用**：不把单个仓库的临时目录、依赖版本或命令写进主 Skill。
- **不重复**：已有规则可覆盖时，补强原规则而非新增近义句。

## 版本策略

- `0.3.x`：重命名、规则澄清、模板或记录机制的小修正。
- `0.4.0`：新增一个完整流程模块，例如 worktree 生命周期或失败恢复状态机。
- `0.5.0`：引入经过样本验证的任务路由指标或持久化协作机制。
- `1.0.0`：在多个不同仓库和任务类型中验证后，核心流程保持稳定。

## 迭代重点

1. **证据化交付**：统一成员交付格式，强制记录实际命令和退出码。
2. **隔离并行**：完善 worktree 创建、命名、清理、合并与冲突恢复。
3. **路由校准**：积累足够复盘样本后，根据返工率、测试通过率、超时率和审查发现数调整通道选择；不依据一次成功或失败下结论。
4. **持久化协作**：只有跨会话、跨仓库或任务依赖复杂时，再考虑 Hermes Kanban 或计划文件。

## 每月维护

每累计 5–10 份复盘或每月一次：汇总重复故障和指标趋势，合并已验证规则，删除被覆盖的条目，更新 changelog 和版本，并用一个中等复杂度真实任务回归验证。
