# Multi-Agent Task Orchestrator

> **v0.4.0：结构化多智能体讨论。** Hermes 会先判断是否值得委派或讨论；必要时组织独立分析、交叉质询、定性归纳、定量方案比较、失败预演和最终执行计划。A2A、Claude Code、Codex 与 `delegate_task` 都是可选通道，不会被强制使用。

一个供 Hermes Agent 使用的个人 Skill：将复杂任务拆解为可验收的工作包，按收益选择 Hermes 直接执行、内部 `delegate_task` 或 A2A peer，并对最终交付负责。

## 核心能力

- **先判断是否协作**：小型、单一且可验证的任务由 Hermes 直接完成；只有分工或讨论带来明确收益时才启动。
- **结构化相互讨论**：在多方案、高不确定性、高风险或用户明确要求时，组织独立提案、Hermes 中继交叉质询、定性归纳、定量评分、敏感性分析和失败预演。
- **选择合适通道**：可使用 Hermes 直接执行、`delegate_task` 或能力匹配的 A2A peer；Claude Code 与 Codex 仅是可选成员。
- **安全协作**：避免同一工作树的并行重叠写入；需要并行写代码时使用隔离 worktree。
- **证据化验收**：不把成员口头“已完成”视为完成；必须检查 diff 并取得真实验收结果。
- **可选复盘**：只有用户或任务契约明确启用时，才保存复盘记录；未启用时不创建复盘文件。
- **授权边界**：未获明确授权时，不提交、推送、创建 PR、部署或发布。

## 使用方式

### 先讨论、后执行

```text
使用 multi-agent-task-orchestrator 管理当前任务。
先不要修改代码，判断是否值得委派或启动讨论。
让成员独立提出方案，再由 Hermes 中继交叉质询；
先做定性分析，再用定量决策矩阵比较方案，输出执行计划。
等待我确认计划后再执行。本次不启用复盘，不要提交、推送或部署。
```

### 允许自动执行

```text
使用 multi-agent-task-orchestrator 管理这个任务：
先判断是否需要讨论或委派；小任务由 Hermes 直接完成。
复杂任务按定性—定量流程形成计划后直接执行；高风险操作先向我确认。
本次不启用复盘，不要提交、推送或部署。
```

### 指定可选成员

```text
如有必要，可让 Claude Code、Codex 或其他能力匹配的 Agent 参与；
不要为了使用它们而强行派工。
```

## 讨论流程

完整讨论仅在存在多个合理方案、较高不确定性/风险、明显架构影响、成员结论冲突或用户明确要求时启动，默认最多两轮交叉讨论：

1. **任务契约**：明确目标、约束、边界、预算、授权和验收。
2. **独立定性分析**：成员互不知晓彼此结论，提出方案、证据、假设、风险、工作量和置信度。
3. **交叉质询**：Hermes 脱敏并转发其他提案摘要，要求成员批评假设、反例、依赖、风险、成本和测试遗漏。
4. **定性归纳与定量比较**：使用带权决策矩阵；每个分数有依据和置信度，必要时做敏感性分析。
5. **失败预演**：审查验收、资源估算、最坏情况、回滚方案、决策门和停止条件。
6. **执行计划**：Hermes 输出推荐方案、放弃原因、分歧、待验证假设、依赖图、工作包、负责人、通道、风险和验收方式。

`a2a_orchestrate` 只负责扇出收集，不代表 Agent 已经互相讨论；真正的交叉讨论必须由 Hermes 显式转发前一轮结果。讨论阶段默认只读，不修改工作树。

## 定性—定量原则

定性分析先回答问题、约束、证据、隐藏耦合、风险、假设和可恢复性；定量分析再估计工作量、时间、成本、风险暴露和方案得分。默认评分范围为 0–5，权重总和必须为 100%。

```text
风险暴露 = 发生概率 × 影响程度
期望时间 = (乐观时间 + 4 × 最可能时间 + 悲观时间) / 6
方案总分 = Σ(权重 × 标准化评分)
```

公式结果是估计和决策辅助，不是事实，不能替代测试。硬约束失败的方案直接淘汰；低置信度的最高分方案先验证关键假设或改用可逆方案。

## 执行通道

| 通道 | 适用情形 |
|---|---|
| Hermes 直接执行 | 小任务、单一可验证工作包、难以安全拆分的改动 |
| `delegate_task` | 短时、边界明确、适合并行的内部子任务 |
| A2A peer | 已配置且能力匹配的外部或本地执行成员；可支持多轮上下文 |

## 可选复盘

复盘不是默认动作，也不是任务完成条件。只有用户或任务契约明确启用时，才创建：

```text
docs/retrospectives/YYYY-MM-DD-<简短-kebab-case-任务名>.md
```

复盘只记录真实证据，包括执行通道、负责人、A2A `context_id`（如有）、变更范围、实际命令和退出码、未运行项、风险与候选规则。未启用时不创建，也不得声称已生成。
