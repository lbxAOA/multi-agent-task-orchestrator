# A2A Code Team Orchestrator

> **v0.2.0：从 A2A 专用编排升级为通用多智能体任务总管。** Hermes 会先判断任务是否值得委派，再按任务边界、能力匹配、风险和验收成本选择直接执行、内部 `delegate_task` 或可用 A2A peer；不会为了使用 Claude Code、Codex 或任何 Agent 而强行派工。

一个供 Hermes Agent 使用的个人 Skill：让 Hermes 拆解复杂工作、选择合适的执行通道、协调实现与独立审查，并基于真实证据验收交付。

## 目标

- Hermes 负责任务契约、拆解、调度、集成和基于证据的验收。
- 根据收益选择直接执行、`delegate_task` 或 A2A peer；已配置的 Claude Code 与 Codex 是可用成员，非硬性依赖。
- 禁止同一工作树内对可能重叠的文件并行写入；并行写代码必须使用隔离 worktree。
- 不将“Agent 声称完成”视为完成：必须检查 diff 并运行验收命令。
- 每个实际委派或多成员协作的任务都会自动生成一份复盘记录，积累成后续 Skill 优化的证据。
- 任何提交、推送、创建 PR、部署或发布，都要求用户明确授权。

## 如何使用

启动新会话后，以类似下列方式发出指令：

```text
把这个任务拆解成合理的工作包；只有在有明确收益时才下派。
需要时让不同成员做实现、独立审查和测试；Hermes 负责整合、验收和自动复盘。
不要提交、推送或部署。
```

用户也可以明确指定可用成员，例如：

```text
如有必要，可让 Claude Code 实现，让 Codex 独立审查；但小任务由 Hermes 直接处理。
```

## 委派通道

| 通道 | 适用情形 |
|---|---|
| Hermes 直接执行 | 小任务、单一可验证工作包、难以安全拆分的改动 |
| `delegate_task` | 短时、边界明确、适合并行的内部子任务 |
| A2A peer | 已配置且能力匹配的外部或本地执行成员；可支持多轮上下文 |

## 自动复盘

对每个实际发生**委派或团队协作**的任务，Hermes 在完成、阻塞或取消时都会自动创建复盘。独自完成的小任务不强制生成，除非存在高风险失败或你要求记录。

### 保存位置与防覆盖

复盘从模板生成，保存到当前项目中：

```text
docs/retrospectives/YYYY-MM-DD-<简短-kebab-case-任务名>.md
```

同一天同名任务会自动追加 `-2`、`-3` 等序号，绝不覆盖历史记录。项目无法写入或不存在该目录时，Hermes 会改存到本 Skill 仓库；如仍不能保存，会在最终报告中明确说明原因。

### 记录内容与真实性门禁

复盘仅记录可验证的事实：

- 任务契约、工作目录、实际团队分工及执行通道
- A2A `context_id`（如有）
- 修改文件与 `git diff` 审查结论
- 实际运行的验收命令及退出码
- 未运行的验收项及其原因
- 独立审查发现、阻塞、风险与候选改进规则

> Hermes 不得把成员口头“已完成 / 测试通过”写作已验证事实。未执行的测试必须标记为“未运行”。

任务最终报告会给出复盘文件路径和一句基于证据的结论。

### 用复盘优化 Skill

复盘中的候选规则仅在以下任一情形下才写回 `SKILL.md`：同类问题第二次发生、一次高风险事件，或用户明确要求改变团队行为。每次写回都要更新版本与 `CHANGELOG.md`，并在下一个匹配任务中验证。

## A2A 可选配置

如果启用 A2A，先用 `a2a_list` 确认 peers，用 `a2a_discover` 了解新 peer 的能力。当前环境可配置 `claude_code`、`codex` 等 peer，但本 Skill 不要求每次任务都调用它们。

不要在任何委派消息中发送密码、API key、token 或 `.env` 内容。
